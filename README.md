# 知行台 · 方法论驱动的个人知识工作台

这是一个用于验证知识管理流程的本地桌面初版。重点不是模拟完整的笔记软件，而是把以下过程嵌入界面：

1. 捕获原始信息；
2. 围绕明确目标开展项目；
3. 通过复盘把经历转化为经验；
4. 把经验提炼为可以再次调用的知识。

## 使用

开发环境使用 Node.js 24 和 npm。首次运行执行 `npm ci`，然后在 Windows 上双击 `启动桌面版.cmd`，或执行 `npm run desktop`。桌面版支持选择文件、拖入画布、独立预览和定位文件。程序优先使用程序目录旁带有 `vault.json` 的 `PersonalVault`，再查找其他磁盘；也可以通过环境变量 `PERSONAL_VAULT_PATH` 指定资料库的绝对路径。

`启动知识工作台.cmd` 是浏览器备用入口，启动后访问 `http://127.0.0.1:4173/`。浏览器支持通过选择和拖拽上传附件，但不能直接取得任意本地文件的完整路径。

桌面版与浏览器备用版启动时均直接读取硬盘上的原始卡片，每次保存都写入资料库，成功后才提示“已保存”。本机缓存即使时间更晚，也不会自动写回硬盘。空卡片目录会显示为空，不会从旧快照或演示数据复活卡片。

换电脑使用同一块移动硬盘时，请保存成功并退出应用后再拔盘；在另一台电脑启动时读取硬盘上的资料。界面偏好、最近访问及活跃日历目前仍使用应用用户配置，不参与判断哪份卡片是最新版本。

## 数据来源、重建与保存保护

| 文件 | 角色 |
| --- | --- |
| `卡片/**/*.md` | 卡片 ID、类型、标题、状态、关系、正文等元数据的权威记录；当前格式以顶部 frontmatter 为机器读取内容，下面的正文是同一份记录的阅读呈现，直接修改下方正文不会导入画布 |
| `系统/自由画布/<ID>.json` | 画布结构、布局、格式和附件块引用的原始文档，不能只从 Markdown 还原 |
| `文件/项目\|知识\|资料/<标题>--<ID>/` | 每张卡片的附件原文件 |
| `文件/项目\|知识\|资料/<标题>--<ID>/封面/` | 用户为卡片选择的自定义封面图片，随卡片保存和目录改名；不计入普通附件或插入画布 |
| `系统/附件清单/<ID>.json` | 附件 ID 与原文件路径、画布来源 ID 的必要映射；需要保留 |
| `系统/tombstones.json` | 永久删除记录；需要保留，防止旧卡片副本重新出现 |
| `系统/latest-state.json`、`cards-manifest.json` | 可重建的整库汇总与卡片清单，应用启动不再以它们取代原始卡片 |
| `系统/附件索引/`、SQLite 全文及语义索引 | 可重建的查询加速数据 |

“数据管理 → 从卡片重建数据目录”独立扫描卡片原文件和附件清单，重建整库汇总、卡片清单、附件查找索引和 SQLite 全文目录，不依赖已有汇总或清单。重复 ID、无效卡片或损坏的原始清单会明确报错；缺失的附件、画布会列入检查结果，不会凭缓存恢复。语义目录由现有按钮按需重建，避免重建基础目录时强制加载大模型。不要把整个“系统”目录当作缓存删除。

保存使用读取时的内容哈希作为版本依据，比较的是卡片原文件和删除记录，画布另有自己的版本检查。只提交实际修改的卡片，未修改卡片使用硬盘当前版本，因此不同窗口分别编辑不同卡片可以先后保存；同一卡片被另一窗口或外部程序修改后，旧编辑会停止保存，不使用最后写入覆盖规则。卡片元数据与该卡片的画布通过同一次保存请求提交，冲突检查通过前不写入原始内容；未变更卡片不重复改写。

保存失败时，编辑窗口保留当前内容；通过“数据管理 → 导出完整迁移包”可导出最后一次未保存提交（包含该次提交的画布），然后选择“重新载入资料库”核对。未保存提交只在当前进程内保留，重新载入或关闭前应先导出。原文件使用临时文件、刷盘和原子替换，降低中途写坏单个文件的风险；多文件保存尚不是跨进程或跨文件系统的完整事务，不支持两份资料库自动合并。

旧版结构化卡片转换为新界面时，会保留 `legacyRecord` 原始字段；当前版本中的未知字段也保留。更新版本的卡片会拒绝降级读取。已经被旧迁移丢弃的字段只能从既有迁移快照恢复，程序不会自动猜测补回。

主界面仍使用原生脚本加载：`home-view.js` 负责首页堆叠、日历及其事件，`vault-session.js` 负责资料库读取版本和保存队列，`vault-cards.mjs` 负责原始卡片扫描与原子文件写入。后续其他视图可沿此边界逐步拆分，无需新增打包器。

## 当前边界

- 已实现：分层导航、随手记双向分类、领域、项目、附属于项目的复盘、项目待办列表、知识、资料、只读详情与显式编辑、可恢复回收站、双向关系展示、数据完整性检查、独立 Markdown 卡片、桌面文件入库、可重建的 SQLite 全文检索，以及按用户明确搜索意图加载的 multilingual-e5-base 本地多语言语义检索。应用启动、普通浏览、精确检索和数据状态检查均不会加载语义模型。
- 已实现画布与附件呈现：项目、知识、资料支持自由画布、画廊与列表、自动及指定封面。独立预览按图片、视频、音频、阅读、模型等类型分组；支持 PDF、文本/Markdown、CSV、PSD 预览、EPUB 阅读和 3D 模型旋转缩放。工程文件使用统一附件卡片。
- 已实现附件存储：每张卡片独立保存到 `文件/项目|知识|资料/<卡片标题>--<卡片ID>/`，附件清单按卡片拆分并建立索引；不同卡片导入相同文件分别保存。新附件保存到卡片时自动建立对应目录。批量迁移工具见 `scripts/migrate-attachment-folders.mjs`。
- 已保存附件以资料库原文件为准，独立预览按需读取当前文件；未保存附件使用临时草稿缓存，保存成功后释放。原文件缺失时显示缺失提示，恢复文件需要明确操作。数据管理提供缓存占用查看和清理。删除画布中的附件块仅移除引用，不会自动删除资料库原文件。
- 已实现双向关系图谱；尚未实现：用较大规模真实检索测试集继续调优、Agent 接入、Windows/macOS 正式安装包。

SQLite 文件位于 `PersonalVault\系统\索引\knowledge.sqlite`。它不是原始数据；删除或损坏后，可在“数据管理”中从卡片一键重建。

默认语义模型位于 `PersonalVault\系统\模型\onnx-community\multilingual-e5-base-ONNX`；278MB 模型权重只在当前开发阶段下载一次，Windows 与 Mac 共用。对应向量目录位于 `PersonalVault\系统\索引\semantic-multilingual-e5-base-q8.sqlite`。不同模型使用不同目录，均可删除和重建；旧 BGE-small 目录保留用于回退。程序及运行组件仍需在每台电脑分别安装一次，但插拔硬盘不需要重复安装。详细取舍见 `向量检索技术决策.md`。

Windows 自动按 DirectML → WebGPU → CPU 尝试推理设备；Apple 芯片 Mac 自动按 Core ML → WebGPU → CPU 尝试。当前 Windows 主机已经验证使用 DirectML。

## 资料库与构建

资料库包含 `卡片/`、`文件/`、`系统/`。个人资料、附件、缓存和模型不提交到 Git。演示数据重置也需要经过硬盘保存检查，不会静默替换已有资料库。

自由画布与文件预览源码在 `experiments/blocksuite-edgeless/`，封面及画廊模块源码在 `experiments/cover-ui/`。根目录已包含生产构建产物；修改这些源码后，安装对应依赖并重新构建：

```powershell
pnpm --dir experiments/blocksuite-edgeless install --frozen-lockfile
pnpm --dir experiments/cover-ui install --frozen-lockfile
npm run build:canvas
npm run build:cover
npm run check
npm test
```

桌面测试与画布浏览器测试使用独立临时资料库及浏览器配置目录，自动启动的子进程以临时目录为工作目录，避免 Windows 拼写检查组件在沙箱环境中将乱码空目录写到项目根目录。相关系统问题见 [Codex issue #41889](https://github.com/openai/codex/issues/41889)。本地截图、探测脚本和测试浏览器缓存位于 `ui-demos/previews/`，不提交到 Git。

## 推荐验证方式

先真实使用一周，只观察三个问题：

- 是否比普通空白笔记更容易开始记录？
- 项目模板是否帮助你提前区分“复用什么”和“自己做什么”？
- 复盘是否真的产生了下一次能使用的知识？

下一版应由上述问题的实际答案决定，而不是单纯增加功能。
